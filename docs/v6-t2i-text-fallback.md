# V6 T2I 纯文本回退设计

## 目标

T2I 是公开帖长图的展示层，不应成为楼主正文和已成功下载图片的单点故障。T2I 超时、返回 503、返回空地址或返回非图片文件时，插件自动改用纯文本，但不改变独立帖子图片的发送顺序、内容和清晰度。

## aiocqhttp 节点布局

正常路径仍为一个合并转发：

```text
LINUX DO 预览（长图）
帖子图片 #1（原图载荷）
帖子图片 #2（原图载荷）
...
```

T2I 失败路径也是一个合并转发：

```text
LINUX DO 预览状态（长图渲染失败，已自动切换为纯文本预览）
LINUX DO 文本预览 1/N（标题、topic ID、楼主正文）
LINUX DO 文本预览 2/N
...
帖子图片 #1（与正常路径相同的原图载荷）
帖子图片 #2（与正常路径相同的原图载荷）
...
```

正文每个节点最多 2,000 字符，最多 6 个正文节点；末尾始终保留原帖链接。正文已在抓取阶段受 `max_content_chars` 限制，超出转发节点容量时会显示“其余内容请查看原帖”。

## 失败边界

- 只有 T2I 调用、返回地址或图片签名校验失败时进入此回退。
- 图片加载器本身会逐图容错；成功得到的 `forward_data_uri` 由正常与回退路径共用同一个节点构造函数。
- T2I 失败结果不写入长图缓存，后续去重窗口结束后的新消息仍可重试 T2I。
- 非 aiocqhttp 适配器不支持 `Nodes`，因此直接返回带标题、正文和原帖链接的纯文本预览。
- Reader 抓取失败、等级限制和帖子不存在仍使用原有的明确错误提示，不会伪装为 T2I 失败。

## 验证契约

发行冒烟分别使用确定性有效 JPEG 与强制 T2I 异常验证两个分支，并通过 OneBot 序列化结果检查：

- 群聊和私聊都只调用一次合并转发接口；
- 回退首节点包含渲染失败状态，正文节点位于图片节点之前；
- 回退路径的图片数量、顺序、签名和总字节数与正常路径的独立图片完全一致；
- 非 aiocqhttp 回退包含标题和原帖链接；
- 冒烟只使用捕获客户端，不向真实 QQ 用户或群发送消息。
