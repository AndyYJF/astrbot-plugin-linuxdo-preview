# V3 图片支持设计

设计日期：2026-08-23

实现版本：0.3.0

## 目标

V3 在原有“Reader 主题 HTML → 楼主首帖长图”链路中加入帖子图片，同时保证一篇图片很多的
帖子不会无限下载、无限扩大 T2I 请求或生成不可控的 QQ 图片。原文顺序、宽高比和图片说明会
保留；任何单张图片失败都只降级该位置，不影响标题、正文或其他图片。

顶部品牌图标和作者图标不再使用小尺寸 CSS 渐变圆，而是使用完全本地的内联 SVG 几何图形。
SVG 在最终 960px 页面上直接栅格化，因此边缘比旧版更清晰。

## 默认上限

| 配置 | 默认值 | 有效范围 | 作用 |
|---|---:|---:|---|
| `max_images_per_topic` | 6 张 | 0–12 | 最多选择并下载多少张；0 表示关闭图片 |
| `max_image_bytes` | 2,000,000 | 128,000–8,000,000 | 单图下载体积和处理后 JPEG 体积上限 |
| `max_total_image_bytes` | 6,000,000 | 256,000–16,000,000 | 单帖所有处理后图片的总上限 |
| `image_timeout_seconds` | 15 秒 | 5–45 | 单张图片请求总超时 |
| `render_timeout_seconds` | 90 秒 | 30–180 | 整张长图 T2I 调用硬超时 |

另有不可配置的防御性处理上限：单图最多 20 MP，处理后最大 1400×2400，JPEG 质量从 82
开始，在超过单图体积上限时逐步降低质量和尺寸。

## 获取与处理

1. Reader Markdown 中的 Discourse 链接图片同时包含 optimized 和 original URL；插件优先保留
   optimized URL，避免为长图下载无必要的原始大图。
2. 只接受 HTTPS 且主机为 `linux.do`、其子域、`ldstatic.com` 或其子域；拒绝用户名、密码、
   非 443 端口和其他主机，避免把帖子内容变成任意 URL/内网请求入口。
3. 重定向后的最终 URL 再做同样的主机检查。
4. 仅接受 JPEG、PNG、WebP、GIF 和 AVIF 图片 Content-Type，并同时检查 Content-Length 与
   实际流式读取字节数。
5. Pillow 只读取第一帧，检查像素数，应用 EXIF 方向，缩小尺寸，将透明背景铺白后转为 JPEG；
   新文件不保留原始 EXIF/元数据。
6. 处理后的字节转为 `data:image/jpeg;base64,...` 内嵌进本地 HTML。T2I 不会收到或主动请求
   帖子图片 URL。

## 降级行为

- 超过张数上限：正文末尾显示剩余图片数量。
- 主机不允许、超时、HTTP/类型错误、损坏、像素或字节超限：原位置显示“图片加载失败或超过限制”。
- 处理后的累计字节达到总上限：后续位置保留占位。
- T2I 整体失败：仍沿用短文本“长图生成失败”，不会退回发送大量正文或原始图片 URL。

## 验证基线

公开样例 `topic/2045356` 共识别 41 张图片，配置选择前 6 张且正文中不保留 CDN URL。本地
三图诊断中两张成功、一张模拟了真实连接失败；最终 960×2,278 JPEG 正确显示两张图片、原位
失败占位、图片说明、38 张剩余提示和 2/41 加载统计。两段全分辨率视觉检查确认宽高比、文字
衔接、SVG 图标和页面宽度均正常。

生产发布必须另外证明：至少一张真实图片在 AstrBot 4.26.2 容器内加载，活跃插件渲染后的
长图高度大于纯文本基线，并通过群聊与私聊 OneBot JPEG 序列化。
