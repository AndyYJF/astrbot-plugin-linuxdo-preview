# V2 长图设计

设计日期：2026-08-23

实现版本：0.2.0

## 范围

V2 把群聊和私聊中的成功响应统一为一张长图。目标是保留 LINUX DO 当前页面的主要视觉语言，
而不是对网页做像素级截图：顶部品牌栏、浅蓝社区提示、醒目主题标题、分类标签、楼主区域、
正文与原帖页脚会保留；导航、侧栏、回复、互动按钮和用户头像不会复制。

帖子图片在本版本不下载、不嵌入，也不把 CDN 地址带入图片。前五张显示带 alt 文本的占位，
更多图片汇总成一条数量提示。下一版再单独评估图片尺寸、下载限额、内容安全和 QQ 长图体积。

## 数据提取

插件把所有支持的链接规范化成 `https://linux.do/t/topic/<topic_id>`，忽略用户 URL 后面的
楼层数字。Reader 请求同时发送：

```text
X-No-Cache: true
X-Target-Selector: #post_1 .cooked
```

Reader 响应头部提供主题标题，选中的 Markdown Content 只对应首帖 `.cooked`。这一方案用一次
外部请求同时得到标题和正文，并避免把后续楼层交给插件格式化器。

## 安全边界

- 仅接受固定 `linux.do` 主机与数字 topic ID。
- 用户正文先移除危险控制字符、HTML、BBCode 与图片 URL，再进行 HTML 转义。
- 自定义模板不加载远程脚本、样式、字体或帖子图片。
- 模板中的 `safe` 内容只来自插件生成且已转义的 HTML 片段。
- 私有/不存在占位、Cloudflare challenge、限流和超限响应在渲染前停止。
- 成功图片按 topic ID 短时缓存；本地临时文件丢失时自动重绘。

## 输出与降级

- 成功：当前 QQ 会话只返回一个 `Image` 组件。
- Reader 失败：返回对应的短文本错误，不转发上游 HTML。
- T2I 失败：返回“长图生成失败”的短文本，不回退发送可能过长的正文。
- 同一主题的并发请求在渲染信号量内二次检查缓存，减少重复绘图。

## 验证基线

公开样例 `topic/2045356` 的最终本地渲染为 960×1,427 JPEG，约 154 KiB。视觉检查确认：

- 中文标题、正文和链接可读；
- 没有二楼内容；
- 没有图片 CDN URL、尺寸元数据或残缺 Markdown；
- 前五张图片为占位，其余 36 张汇总显示；
- 页面没有横向溢出或异常空白。

这只证明当前样例与渲染端点；生产 AstrBot 4.26.2 的兼容性和 QQ 客户端接收仍需部署后验证。
